Freight forwarding & logistics ERP

Documentation

FreightFast is an enterprise-grade freight forwarding ERP — shipment requests, quotations, job files, freight documents, finance closeout, and a client portal, in one system. This page covers what it is and everything it does. For setup steps, see the Installation Guide.

01 — Read first

What FreightFast is

A single Next.js application with a MySQL-compatible database. There's no separate backend service to stand up — the app, API routes, and background job endpoints all ship from the same codebase.

Three surfaces, one app

The build serves three distinct sign-in surfaces from the same deployment: an operations dashboard for company staff (quotations, shipments, finance), a platform console for the SaaS operator managing tenant companies, and a client portal your customers use to track their own shipments and documents. Routing between them is host-based, configured during installation.

Multi-tenant by design

Every record belongs to exactly one company, and within a company, to exactly one branch. If you're installing this for a single freight forwarder, you'll use one company with one or more branches; the platform console exists for cases where you're operating this as a SaaS across multiple client companies.

Role-based from the ground up

Seven predefined roles — Company Admin, Operations Manager, Documentation Officer, Accounts Officer, Sales Executive, and two more — gate every module, action, and record. Permissions are enforced server-side on every request, not just hidden in the UI.

04 — 30-second check

Is your hosting compatible?

Ask your host, or check your control panel, for these three things.

06 — Confirmed to work

Where it runs

Anywhere you get a real Linux server with SSH access and can run npm run build && npm run start as a long-lived process.

Any VPS provider

DigitalOcean, Linode, Vultr, Hetzner, Contabo — a basic droplet/instance is enough to start.

AWS EC2 / Lightsail

Full control over the instance; pair with RDS for a managed database if desired.

Azure App Service

A ready-made GitHub Actions workflow for this is already included in the repository.

Self-managed VPS over SSH

A ready-made GitHub Actions workflow for SSH-based deploys is already included in the repository.

Docker host

Any server or platform that runs a Dockerfile you build from this codebase (Next.js standalone output works well in a container).

Serverless platforms (Vercel, Netlify, and similar): possible, but not the primary supported path. They require extra configuration for the database connection pooling Prisma needs under serverless invocation, and for scheduling the two background-job endpoints (which need a real cron trigger, not just an HTTP route). The two deploy workflows bundled with this codebase target a VPS and Azure App Service specifically because both give a persistent process and a normal system cron.

07 — Keeping it running

Process management & scheduled jobs

A process manager, not just npm run start

Running npm run start directly in a terminal stops the moment that terminal closes. In production, run it under a process manager that restarts it automatically — pm2, a systemd service, or a Docker container with a restart policy all work.

A reverse proxy in front of it

Next.js serves plain HTTP on its own. Put Nginx (or equivalent) in front of it for TLS/SSL termination and to serve on ports 80/443.

Cron access for two optional features

Automated external notification delivery and recurring-task generation both rely on something calling a protected URL on a schedule — a normal Linux crontab entry, or any external scheduler that can make an HTTPS request. Both features work perfectly well without this configured; they just don't run on autopilot until it is. See the Installation Guide's Background Jobs section for the exact commands.

10 — Required

Database

The only hard external dependency. Every record — shipments, quotations, invoices, users — lives here.

Self-hosted: install MySQL 8.0 or MariaDB 10.6+ on the same server as the app. No ongoing cost beyond the server itself.

Managed: a hosted MySQL-compatible database (e.g. Amazon RDS, DigitalOcean Managed Databases, PlanetScale) removes the need to administer the database server yourself, at the cost of the provider's hosting fee. Either path works — set DATABASE_URL to point at whichever you choose.

11 — Optional

File storage — Azure Blob Storage

Powers the Shipment Document Vault — uploaded freight documents, HBL/HAWB copies, and other shipment files.

Without AZURE_STORAGE_CONNECTION_STRING configured, document upload is unavailable but the rest of the app functions normally. Azure's free-tier credits for new accounts are typically enough to evaluate the feature before committing to a paid plan.

12 — Optional

AI features — Google Gemini

Ten of the fifteen AI-assisted tools (Document Reader, Document Checker, Quotation Generator, Email Generator, and others) call the Gemini API. The remaining five are deterministic and need no external service.

Get a key from Google AI Studio and set GOOGLE_GENERATIVE_AI_API_KEY, plus AI_ENABLED=true. Gemini's free tier covers moderate usage; heavier volume moves to its paid pricing. Without a key configured, every AI feature — including the five deterministic ones, which share the same permission gate — stays switched off.

13 — Optional

Delivery channels

In-app notifications always work with no setup. These three only govern sending a copy externally.

Email — any SMTP provider

Point SMTP_HOST/SMTP_PORT/SMTP_USER/SMTP_PASS at any SMTP relay — a transactional email provider, your own mail server, or even a personal account for testing. Pricing and free-tier limits vary by provider.

WhatsApp — Meta WhatsApp Cloud API

Requires a Meta for Developers app with the WhatsApp Business Platform enabled. Meta bills per conversation once you're past its free tier — see Meta's own pricing for current rates.

SMS — any SMS gateway

Plug in whichever regional SMS API provider you prefer via SMS_PROVIDER/SMS_API_KEY. Cost is per-message and varies significantly by provider and destination country.
